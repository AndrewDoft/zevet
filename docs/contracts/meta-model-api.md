# Meta Model API (Muse Spark) — contract note

**Verified 2026-09-27** against Meta's own developer docs, fetched this session:

- https://dev.meta.ai/docs/quickstart
- https://dev.meta.ai/docs/models
- https://developer.meta.com/ai/resources/blog/build-with-muse-spark/

## Endpoint

- **Base URL:** `https://api.meta.ai/v1`
- **Auth:** `Authorization: Bearer <MODEL_API_KEY>`
- **Documented env var:** `MODEL_API_KEY` (quickstart: "For the OpenAI-compatible
  formats, that's three values: base URL `api.meta.ai/v1`, your `MODEL_API_KEY`,
  and model `muse-spark-1.1`.")
- Quickstart states the API is "drop-in compatible with the OpenAI SDK, the
  Anthropic SDK, and OpenAI-compatible agent CLIs" — point an existing client at
  this base URL with this key and keep the rest of the code. Named integrations
  include **OpenCode**, Goose, Roo, Continue, LangChain, LlamaIndex, and the
  Vercel AI SDK.

| `muse-spark-1.1` | |
| `muse-image-1.0` | image, not text — out of scope here |
| `muse-voice-transcribe-1.0` | audio, not text — out of scope here |
| `sam-3.1` | segmentation, not text — out of scope here |

All Muse Spark versions "share the same modalities and context window":
**1,048,576 input tokens / 131,072 output tokens.**

Zevet's picker offers only `muse-spark-1.3` and `muse-spark-1.1` — the two ids
the quickstart itself names as what you point a plain OpenAI-compatible client
at. The `-contributor` ids are the ones opencode's own free "zen" tier already
exposes (see `board/src/lib/models.generated.mjs`, generated by
`board/scripts/sync-models.mjs`, which already carries `NAME_ORG` entries for
`muse-spark` and `muse-glimmer` -> `meta`); that path needs no direct key and
predates this change.

## Streaming, tool calling — confirmed present, fields not fetched

The docs nav lists a **Responses API** (`/docs/api-reference/responses`,
`/docs/api-reference/responses/create-response`) and a dedicated
**Tool Calling** page (`/docs/tool-calling`), and the quickstart's own prose
claims "agent-ready primitives out of the box: parallel tool calls, streamed
tool-call arguments, reasoning that carries across turns." Because the API
states it is OpenAI-compatible, the request/response shapes (SSE streaming
deltas, a `tools` array, `tool_calls` in the response) are assumed to follow
OpenAI's own Chat Completions/Responses conventions — that is the entire
premise of "drop-in compatible" — but the exact JSON field-by-field shape was
**not fetched field-by-field in this session** (the WebFetch summaries did not
surface a raw example). Anything that calls this endpoint directly must
confirm the exact response shape against a live call, or against
`/docs/api-reference/responses/create-response`, before depending on a field
name.

## What zevet actually does with this

Zevet has **no existing direct HTTP client for any model provider** — every
model zevet can run today is run by spawning a CLI (`claude`, `codex`,
`opencode`) that does its own API calls; even Gemini, already listed in the
picker (`board/src/lib/gemini-models.mjs`), has "no adapter runs it yet"
(model-choice.tsx). So "reuse an existing OpenAI-compatible client path" does
not describe any code that exists in this repo. Muse Spark is added to the
composer's model picker the same way Gemini already is: **listed, described,
shown only when a key is detected, but with no execution adapter** — see
`board/src/lib/muse-models.mjs`, `constants.ts`'s `MODELS.meta`, and
`composercontrols.tsx`. Building a real execution path (either a direct HTTP
client using Node's built-in `fetch`, or wiring Muse Code — see
`docs/contracts/muse-code-hooks.md` — as a fourth spawnable CLI) is future
work, not fabricated here. See INSUF-009.

A **Meta API key can already be saved in Zevet Settings** the same way an
OpenAI or Anthropic key can: `"meta:api_key"` was added to the existing
provider/credential table (`CREDENTIAL_KINDS` in `settings.tsx`, `CREDENTIAL_ENV`
in `desktop/main.js` and `hub/server.mjs`), mapped to the env var
`MODEL_API_KEY`. Nothing currently spawns using it — see above — but it is
stored, encrypted, and never sent to the hub, identically to every other
provider's key.
